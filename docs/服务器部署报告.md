## 二、部署架构

三个容器，同一 Compose 网络 `project_default`：

| 容器 | 镜像 | 作用 | 端口 |
|---|---|---|---|
| `knowseek-db` | `pgvector/pgvector:pg16` | PostgreSQL 16 + pgvector 向量扩展 | 5432（仅容器内） |
| `knowseek-backend` | `project-backend`（自建，1.05 GB） | FastAPI + uvicorn，提供 133 个 API | 127.0.0.1:8000（仅本机） |
| `knowseek-frontend` | `project-frontend`（自建，96 MB） | Nginx 托管 Vue3 构建产物 + `/api` 反向代理 | 0.0.0.0:80 |

数据持久化：命名卷 `knowseek-data` 挂载到后端 `/data`（`chroma_data` 向量库、`uploads` 上传文件）。

> **端口变更说明**：原 `docker-compose.yml` 将后端 8000 直接映射公网。本次改为 `127.0.0.1:8000`，公网统一走 Nginx 的 `/api` 反代，避免后端裸奔暴露 133 个接口。已在仓库提交（`5e86689`）。

## 六、上线前必须补齐的配置

以下两项未配置时系统可运行，但功能受限：

### 1. 邮箱 SMTP（否则注册/找回密码无法收码）

当前 `server/.env` 中 `DEV_PRINT_CODE=true`，验证码**只打印在后端日志**、不发邮件，属于临时验证方案。

配置 QQ 邮箱授权码后：

```bash
cd /root/project
vi server/.env
# MAIL_USER=你的QQ邮箱
# MAIL_PASS=SMTP授权码
# MAIL_FROM=你的QQ邮箱
# DEV_PRINT_CODE=false      # 生产必须关闭
docker compose up -d backend
```

### 2. DeepSeek API Key（否则 AI 问答走本地降级模式）

```bash
vi server/.env
# DEEPSEEK_API_KEY=sk-xxxx
docker compose up -d backend
```

## 八、本次部署踩到的 3 个坑（已修复并推送）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | `pip install` 报 `Invalid requirement: '（内容由AI生成，仅供参考）'` (line 30) | `server/requirements.txt` 末尾混入一行无 `#` 的中文说明 | 删除该行并统一 LF 行尾（`825f074`、`53661f4`） |
| 2 | 容器启动报 `exec: "uvicorn": executable file not found in $PATH` | `server/Dockerfile` 多阶段构建只 COPY 了 `site-packages`，未 COPY `/usr/local/bin` 中的 console_scripts | 增加 `COPY --from=builder /usr/local/bin /usr/local/bin`（`be31032`） |
| 3 | `docker compose up -d` 超时中断后容器停在 `Created` 不启动 | 首次需下载 pgvector 镜像，SSH 长连接被中断，容器创建成功但进程未起 | 第二次执行 `docker compose up -d` 即正常启动 |

## 九、已知问题（不阻塞运行）

1. **启动日志早期出现 `relation "doc_chunk" does not exist`**：后端在 `create_all` 之前先尝试加载历史向量切片，属启动顺序问题。表建好后自动恢复正常，仅日志噪音，可后续在 `app/main.py` 调整初始化顺序消除。
2. **`/api/openapi.json` 经 Nginx 返回 404**：Nginx 的 `proxy_pass http://backend:8000` 不做前缀剥离，而后端路由自带 `/api` 前缀，`/api/health` 等业务接口均正常；仅文档类路径不合规，不影响业务。
3. **服务器内存 3.6 GB 偏小**：当前三容器常驻约 500 MB，够用；若后续上 OCR/大文件解析建议升配到 4 GB 以上。
